## 数值依据

以后轴中心为原点，前向为x、左向为y。运动学为：

`yaw_rate = v * tan(../delta) / wheelbase`。

每10ms对恒定速度/转角使用解析圆弧积分，避免欧拉法制造额外弯道误差。最新轴距0.19m、后轴轨迹半径0.50m对应等效转角`atan(../0.19/0.50)=20.8068°`。这个角度不能证明±130µs能实现同样转向能力。新C1轮胎显示采用同一曲率计算内外前轮角度。结构细节与尺寸来源见`C1车模与实测参数.md`。

针孔相机投影采用独立水平焦距fx、垂直焦距fy，主点cx/cy和向下俯角theta。平地直道宽度满足：

`width_px(../row) = road_width / height * [fx*sin(../theta) + (../row-cy)*(../fx/fy)*cos(../theta)]`。

44/167两点给出斜率123/86=1.43023px/行。固定height=0.27m、road_width=0.50m、cy=59.5、fy/fx=1时，theta=39.4368°、fx=73.2708px、水平视场104.1288°。

如果fy/fx未知，俯角与缩放比存在耦合。例如允许fy/fx约1.2166，也能构造接近20°的两点匹配方案，并得到另一组有效焦距；因此39.4368°只是默认假设下的解。标称130°和几何畸变≤1%不足以解除这种不确定性。

在真正20°俯角时，光轴地面交点为0.27/tan20°=0.741819m（镜头前），按最新镜头距底板前缘0.15m计算，约为底板前缘前0.591819m。默认39.4368°条件解的交点更近；软件投影和视锥按实际选用参数计算。当前默认hfov=120°，两点拟合只在用户主动点击时覆盖视场值。

## 代码接入

`vendor/src`为原始应用C文件副本，`vendor/include`和`vendor/config`为原始头文件副本。`native_bridge.c`是仿真专用硬件边界，保留主机控制输入映射和原状态机。不复制或运行整套RT1064 SDK，也不模拟实际主循环竞争、ISR延迟或GPIO/PWM硬件行为。

运行时调参以新生成配置头文件为入口，原始副本不被修改。DLL签名由桥接、所有复制源码/头文件及编译期参数共同计算。每个DLL的原视觉算法具有静态状态，同一进程只支持一辆活动仿真车；并行实验使用独立进程。

相机时序独立于10ms控制循环；不发送新图像时保留原序号和时间，不伪刷新。编码器以整计数采样，保留量化；反馈输入是经方向归一化后的轮速，不再把原始右侧负号重复施加一次。舵机服务确认是仿真适配层的正常服务假设，没有声称验证原硬件竞态。
