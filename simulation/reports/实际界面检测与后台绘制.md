# 实际界面检测与后台绘制

检测日期：2026-10-12。

通过 Windows 文件资源管理器启动仿真，在用户桌面使用 computer-use 实际点击并查看窗口。检测内容包括首屏、3D 场景、启动运行、跟车开关、拖动旋转、最小化恢复、暂停、应用并重置、2D 页面、相机及扰动参数页、关闭窗口。测试窗口关闭后 Python 进程已退出。

## 修改

- 运行中的 3D 图像由单个后台线程生成。提交前复制车辆状态、参数、轨迹和赛道缓存对象；后台不运行控制算法，也不操作 Tk。主线程接收完整图像，验证仿真对象和视角参数后再显示。旧任务不积压，切换参数和视角时丢弃不匹配的结果。
- 按帧绘制开始时刻计算刷新节奏，避免每帧绘制耗时额外叠加到等待时间中。
- 仅跟车视角跳过完全位于画布之外的道路多边形；全景保留原来的绘制路径。

## 实际交互计时

数据来自真实桌面窗口中的计时检测，不同轮次的车辆位置、交互操作和系统负载并不完全相同，因此属于观察性对比，不是严格控制条件的性能基准。

| 指标 | 修改前 | 后台绘制版 |
| --- | ---: | ---: |
| 主线程 refresh 中位耗时 | 约21 ms | 约9 ms |
| 主线程 refresh 第95百分位 | 约34 ms | 约15 ms |

记录文件：interactive-ui-before.json、interactive-ui-after.json。refresh 耗时不包含后台绘图，也不能当成屏幕帧率或点击到显示的总延迟。记录仍有约250 ms量级的偶发事件间隔，不能据此宣称所有卡顿或残影已完全消失。

## 检查结果

- 12 组全景/跟车视角、不同角度和画布尺寸的像素对比全部一致：viewport-culling-check.json。
- 六组最小化恢复检查通过；隐藏期间仿真冻结，恢复后相机像素与数据源一致，每个画布仍只有一个图像项。本轮自动检查恢复至就绪约65–95 ms：window-lifecycle-checks.json。它与实际桌面点击测试分开记录。
- 参数工作流检查通过：六行标定、旧参数兼容、扰动可复现、数字输入、单列布局、停车后图像记录。parameter-workflow-checks.json。
- 早期生命周期检查因测试在首屏准备结束前运行而失败；已将测试改为等待窗口移入可见区域，然后重新运行通过。失败属于检测时序，未计入通过结果。

修改前 app.py 和 render.py 已备份至 before-interactive-render-fix.zip。Autodrive 未修改。真实桌面检测首次启动记录约1.45秒；自动检查在不同负载下时间更长，启动耗时不是固定保证。
