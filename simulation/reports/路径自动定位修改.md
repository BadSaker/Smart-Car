# 路径自动定位修改

日期：2026-10-12。

启动入口不再写死用户名或 Python 安装目录。Windows PowerShell 5.1 在启动时查找64位Python，先检查 SIMULATION_PYTHON 和项目自带环境，再检查上次成功路径、Python启动器、PATH、Python安装注册表及用户安装目录。每个候选都检查解释器位数、版本和Tkinter/NumPy/Pillow模块及相关包元数据，实际导入错误由启动程序另行记录。缓存不是固定依赖，失效后重新查找；跳过Windows Store别名，不触发商店、不扫描整个磁盘、不自动安装软件。

C工具链只在需要生成新DLL时查找：SIMULATION_CC、项目内工具链、PATH、常见MinGW/MSYS2布局、最后才是已有Vivado目录。检查gcc -dumpmachine，拒绝32位或其他目标。加载已有匹配DLL时不查找编译器，也不要求Vivado目录存在。当前机器PATH中的GCC目标mingw32，被拒绝；备用Vivado GCC目标x86_64-w64-mingw32，可用。这次没有复制或安装独立工具链。

项目资源、编译缓存和默认数据目录仍相对simulation定位。系统字体根据WINDIR/SystemRoot定位。用户指定的保存路径仍尊重用户选择，不进行磁盘搜索。历史备份和历史会话抓取脚本中的绝对路径保留为历史记录，不参与正常启动。

验证：

- 自动找到本机64位Python 3.13及已安装依赖，记录在launcher-runtime.json和launcher-dependencies.json。
- 经新的PowerShell启动链路打开完整Tk界面并正常关闭，摄像头图像376×240、默认C DLL已加载：discovered-startup-check.json。
- 将查找入口复制到含中文和空格的目录，写入无效旧缓存，并提供缺少NumPy的项目虚拟环境；该环境被拒绝，然后自动找到可用Python。详情在迁移路径 检查/reports/launcher-dependencies.json。
- 在不允许调用编译器查找函数的条件下，已有默认DLL仍正常加载；新控制参数实际编译生成64位DLL：tool-discovery-check.json、compiler-discovery.json。

上述迁移验证是本机目录和环境模拟，没有在另一台物理电脑上验证。自动搜索不会替代安装缺少的依赖，也不等于已经完成独立EXE打包。
