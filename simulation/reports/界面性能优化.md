# 界面性能优化记录

日期：2026-10-11。修改范围：仅`simulation`，保留完整赛道与A/B独立标线。

## 已定位的原因

原UI每次刷新都用密集中心线重画整个2D道路，并逐个构造、投影和排序数千个3D面片；暂停时也持续重复绘制。仿真每批可占用主线程45ms，再叠加完整绘制和60ms等待。鼠标拖动事件同步触发重绘，无法及时处理下一个输入。

基线测量见`performance-before.json`及其profile。单步仿真中位数0.751ms，而固定尺寸2D/3D绘制为128.148/114.274ms，因此先优化UI渲染，无需修改车辆、赛道或C算法。

## 改动

- 2D静态赛道按当前窗口尺寸缓存，车体、轨迹和可选标线单独绘制。
- 3D道路的世界坐标网格一次生成，投影使用NumPy批量运算；固定视角缓存背景，跟车和旋转时重新投影。
- 背景仅保留最近一个尺寸/视角，避免拖动导致缓存无限增长；字体和原始赛道图不再重复读取。
- 重用同尺寸Tk图像对象。暂停且画面未变化时不提交图像、不重绘图表。
- 单批仿真计算预算从45ms降至6ms，在批次间让出Tk事件循环；显示目标30Hz，10ms仿真步长与摄像头时序不变。
- 拖动、缩放、跟车和标签页事件合并为下一次UI绘制，绘制最新视角。
- 回放可在6ms预算内推进多个到期帧，避免8倍速时每个UI回调只播放一帧。

## 测量结果

同一台机器、相同默认完整赛道，固定760×550视图。耗时为缓存稳定后的中位数，不包括首次构建静态背景。

| 操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 2D绘制 | 128.15ms | 1.90ms |
| 固定视角3D绘制 | 114.27ms | 2.44ms |
| 3D旋转、重新投影 | 原方法每帧完整生成/投影 | 7.91ms（P95 8.83ms） |
| 跟车、重新投影 | 原方法每帧完整生成/投影 | 7.18ms（P95 8.95ms） |
| 仿真单步 | 0.75ms | 0.79ms，模型未改 |

实测Tk事件循环：用20ms定时回调测量超出预定时刻的额外延迟。优化后暂停、2D正常运行、3D正常运行、3D八倍目标的P95分别约11.8、19.6、36.8、19.9ms；本轮暂停阶段图像提交次数为0。旧版本在同一测试中P95约410～511ms。后台负载会影响这些数字，倍速是目标值，不能保证所有机器达到8倍。

## 使用

已经打开的旧进程不会自动加载新Python代码。请先关闭旧仿真窗口，再双击`启动仿真.cmd`。参数文件和已有实验保留。首次加载、首次尺寸变化或重新编译C配置仍可能有一次短暂等待；稳定运行和拖动不再持续重建整个场景。
