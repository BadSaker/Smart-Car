## 执行范围和结论

用户批准的是视频逐帧诊断、源码核对和具体修改方案。本轮没有修改生产源码、配置、现有测试或发布固件，没有编译Keil固件、烧录、操作车辆或执行Git提交/推送。仅编译Windows诊断DLL，直接调用car中的原实现，输出保存在报告证据目录。上一任务已将源码超速故障阈值改为6000，未编译烧录；该修改本轮保持。

现场反馈优先于历史合成测试。当前已查明：

1. Q接近100/0有明确代码原因：几何轮迹全通过后覆盖原评分，无效帧最后又清零。单降Q门槛不能修复valid=0。
2. 2500以上没有独立快速撤动力逻辑；6000硬故障阈值只把原立即停车推迟到更高速度。主机实测输入5999后仍有较大正PWM。
3. 斑马线存在“条纹已识别，但通行路径被拒绝”的问题；不能统称完全没有识别。
4. 近似整段回放未进入环岛；前向分支/岛边/缺口条件经常缺失。需要处理入口证据链及阶段保持，不应仅修改确认帧数。
5. 近距离砖截图可触发右侧障碍和向左偏移，录像中较远砖没有形成候选；识别范围、连续性、场景位置和运行模式需要区分。
6. “第二次过线后继续行驶并逐渐减速”可设计实现，但当前500mm起点、100mm/s限速、10秒超时和900mm配置上限不能直接支持用户提出的新方案。

本报告中的回放不是车上实际状态重建。录像没有固件身份、车端时间戳、运行状态、轮速和里程。用户尚未说明是否含手推、拿起或重新启动；不把一圈录像直接认定为自动闭环整圈成功或失败。

## Q为什么主要只有100和0

源码位置：car/src/track_vision.c:1537、1570、1814、1866。

第一层vision_path_quality按实测行/双边行计算observation_confidence，原本是连续值。第二层vision_path_reliability结合近远白区、锚点、抖动生成连续分数。

之后几何轮迹检查要求采样点全部通过；通过时重新执行：

```c
out->confidence = good*100U/total - 15U*inferred/total;
```

全部当前可见点通过时good等于total、inferred为0，结果就是100。视野外由模型推断时会有小幅扣分。任一路径最终无效时又执行：

```c
if (!out->valid) {
    out->fault |= TRACK_FAULT_PATH_LOST;
    out->geometry.valid = 0;
    out->confidence = 0;
}
```

因此几何检查的布尔结果覆盖了前面的连续证据分数。Q不是统计概率。显示100不表示边线全部可靠，显示0也不能区分无图像、局部像素拒绝、近场失路和轮迹拒绝。

故障后另有诊断冻结：autonomous_drive_tick在故障状态会保留触发时的路径状态，trace在autonomous_control.c锁存first_bad/fault_frame；屏幕读取的是控制状态，不是独立的当前视觉结果。这是原设计用于保留故障，不代表实时画面没有继续采集。

修改建议：保留原始观测Q、路径支持评分和几何valid/reject三者，不再用全通过比例覆盖支持评分，也不为显示而把无效帧的观测值清零。初次调整先保留控制评分的可比定义；若改变控制Q公式，必须同时重标门限，不能直接把较低的原始单边Q塞回现有控制门槛。实时诊断Q与故障冻结Q应区分，避免覆盖first_bad。只为用户要求的实时Q做最小显示字段调整，需要明确屏幕冻结约束的本次例外，不改图像/图传流程。

## 弯道与LOST

现状：普通门限45，已运行且本帧可靠外侧模式40，已确认有效元素35。外侧模式要求两帧确认、至少8连续行、近场70%及远场50%实测覆盖等。O0表示未实际启用，不会获得40门限。照片Q40/45说明该帧没有获得外侧许可，不等于“把普通门槛也设40即可解决全部问题”。

控制侧按新的帧序号累计坏帧，第一坏帧撤动力并暂时保持方向，连续3个坏帧锁存LOST；不是固定30ms，也不是PIT每跑3次就LOST。源码：autonomous_drive.c:197、229、260。

当前回放存在急弯/开阔口的有效路径拒绝，28秒附近静态样本V0，32秒附近有几何轮迹G2拒绝。视频重放与停车照片的Q值并不完全一致，受固件身份、运行模式、图像叠加等限制。

可放宽的是有限证据缺口，不是把所有拒绝都当可通行：

- 普通弯道继续使用当前可见外侧边，减弱对固定远场覆盖及内侧出画形态的同时要求；优先使近场、外侧连续性与实际可见预瞄窗口一致。
- 对单/双行小接缝或噪点，拟议允许局部低占比、非连续、非轮胎危险区域的拒绝点；当前明显障碍/真实路外不能被白区总分盖过。
- 将硬失路与弱证据分开。可见近场仍可通行的短时弱证据进入有限恢复状态，降速/撤动力、保持最近合法方向；恢复后平滑接管。完全无近场可行路径、真实碰撞路径、明显越界仍立即撤输出。
- 建议用“新帧+最多150ms/100mm”的有界恢复试验，取先到者；参数为待回放校准初值，不是已验证实车值。不能只把3坏帧无限增加，或允许高车速盲走。

## 环岛

源码：vision_gap:356、vision_forward_branch:514、vision_near_island:563、vision_elements:716。

当前候选要求有界单侧开口、对侧支持、前向白色分支、较直来向、路径有效、不在斑马线/冷却期等；岛边还要求连续跨度12行、凸性2px持续3行。候选3帧后进入APPROACH；进入ENTER又需同侧缺口、分支和岛边、有效路径、开口到达60行等连续3帧。APPROACH缺口/分支消失或被判十字连续3帧可撤销。它确实是多重同时条件，容易错过实际视角下短暂的完整证据。

全部近似帧中左侧前向分支拒绝位4出现在4570/4579帧，左侧岛边拒绝位8出现在4519/4579帧；右候选计数始终0，左候选只短暂达到1～4。零里程会影响后续阶段，但没有进入APPROACH这一结果不能单用里程缺失解释。由于图像和运行状态限制，这仍不能证明实车的某个候选正是在同一位被拒绝。

另一个明确行为：main.c:103在非自动active时，每帧调用track_vision_reset。停车/手推图传下多帧环岛、外侧及砖候选不能正常累计，这是观测模式和行驶模式的差异。若录像含手推，不能把它当自动状态机完整回放。

建议：识别“入口区域”后有界保留侧别；用最近少量新帧累计互补证据，不要求开口/分支/岛边在每一帧同时完美出现。先试3帧中2帧确认、约150ms候选容错，并要求当前近场方向和可通行轮迹支持；来向用近场可信边，不让远场分支污染来向。入口动作和出口重新确认仍独立。不能简单取消分支和岛边，否则普通弯、十字、反向汇入口容易误入环。

完整逐组目视后的定位：帧2701～2704（54.02～54.08秒），左候选依次达到1、2、3、4，但ring_left_reject始终为8，即缺少岛边证据。候选达到原3帧门槛仍不能进入APPROACH，明确说明仅把确认帧数从3改2不能解决这个样本。可优先试验将岛边连续跨度12→8行、凸性2→1px、凸性连续3→2行，并保留当前缺口、可通行近场和来向一致性；这些是待反例验证的试验值，不是已批准/已实现值。前向分支的漏检还须检查测量窗口、预期宽度和支路方向，不能用该组8位拒绝解释全片所有漏检。

## 斑马线

实物为横向排布的7根沿行驶方向延伸黑条。现有检测是横向黑白跳变，并非扫错方向。每段最少2px、至少6次稳定转换、黑占比20%～80%、连续3行；后续还要求真实外边和几何轮迹可通行。

静态近似回放：1秒帧Z1，但V0、G2、zebra_reject=2；77秒帧同样Z1/V0/G2。全帧76～91.58秒区间754帧识别条纹，其中526帧最终路径无效。这说明至少一部分问题是“识别后路径拒绝”。插值和直接亮度结果不同，数字仅定位链路，不是识别率。

建议分级放宽：

- 远场预告可用4次稳定转换、连续2行；正式起/终点确认仍要求更充分条纹、当前车道位置和至少2个不同新帧。先区分预告/确认，避免一条接缝就判斑马线。
- 跟随道路预测中心搜索条纹，避免始终固定93列扫描使偏入/斜入丢失有效条纹。
- 通过已确认区域时，根据当前外侧道路与前后锚点修复穿越走廊；灰度黑条只在该标记区域内可通行。保持对区域外红砖/路外的拒绝。
- 扩展区域边缘时使用实际倾斜条纹形状，不把4行固定扩展当作所有斜入情形的完整覆盖。对轮迹采样落在条纹边缘的拒绝逐点核查，按局部容错修正。
- 保留起点已通过、离开重武装、最小圈时/圈程和返回确认，避免同一片标记重复触发终点。

## 红砖

现有机制检测的是灰度连通白走廊的单侧有限内凹，不是颜色语义。要求4～50连续行、前后正常锚点、对侧连续、两个新时间帧确认；按车宽+20mm余量限制中心，消失后按里程保持再回归。

视频20秒样本中砖位于当前道路右缘外侧/邻接灰背景，阈值208下与外侧背景连成暗区，没有形成符合判据的内凹候选；不能仅凭画面有砖就要求改线。贴边高物体还存在立体投影，顶部和地面占道并不一致。

提供的近距离截图经裁剪回188×120、近似去叠加后，连续三次静态输入可确认右侧障碍，最终V1/Q100、obstacle.side=2，路径向左偏。此结果证明当前实现对该外观存在可触发路径，不证明实车能及时避开。静态重复不等于真实运动确认。

建议优先改善初现/贴边/底部裁剪时锚点不足和低占道比例漏检，在当前可靠空侧边下允许短时锚点继承；保持单侧假设、当前空侧净宽和真实轮迹验证。先输出障碍候选/确认/偏移证据，再决定缩小侵入比例阈值，避免把普通弯道、阴影与接缝都当砖。图传停着看不到偏移也可能是每帧reset造成，不直接修改冻结主循环。

## 轮子悬空与2500抑制

当前速度是10ms编码器增量换算，左右符号调整后直接执行6000硬故障判断；PID测量另有alpha=0.30滤波，正常PWM每10ms最多下降12‰。源码autonomous_drive.c:56、180、311～338。

主机输入实验从相同运行状态输入单轮2501、3000、5999，第一拍该轮PWM仍为633‰，50ms后573‰，均未故障；6001第一拍两轮PWM均为0、故障6、active=0。它不能保证悬空后迅速抑制转速，用户的担心有软件证据支持。

拟议修改：新增2500mm/s快速抑制阈值，原始可信轮速一越限就立即撤该轮正向动力，绕过普通下降斜坡；不锁存OVERSPEED。单轮撤动力时限制另一轮继续加速，避免非对称动力放大偏航；不自动反转。回落到例如2200mm/s以下并连续3个新编码器采样后，按原上升斜坡恢复，PID按实际输出跟踪，避免积分恢复冲击。这些恢复值为待测试初值。

6000暂作为独立异常硬故障保留，是否更改需明确选择；2500～6000的短时可恢复限速不再等同故障。若仍持续加速，不能以“不报错”为目标忽略控制失效。

编码器计距目前直接取两轮平均，没有打滑标记。例：车身没前进而一轮4000、另一轮1000，10ms会累计25mm。拟议把轮速抑制/突变期间里程标为不可信，不将异常计数推进终点、环岛相位或避障清除。不能无条件取较慢轮：弯道本来存在正常差速，应识别可信窗口；纯双编码器不能证明真实地面位移，双轮同时滑转仍需实测约束。

## 起终点与用户补充的逐渐减速

用户明确：发车时前轮在斑马线前；返回停车时后轮经过斑马线。用户进一步提出“视野经过斑马线后额外行驶1米”和“按照终点前原有速度逐渐减速”。

当前实现第一次近场确认记录起点，第二次满足8秒/5000mm门槛后记录FINISHING，从第二次近场确认位置计500mm；接近/穿越都把基础上限降为100mm/s，现有目标斜坡每10ms最多降8mm/s；最终靠累计距离、新有效离线帧决定DONE。它没有按剩余距离制动。

不能只把500改1000：

1. 当前参数校验拒绝>900mm。
2. FINISHING只有10秒；100mm/s额外行驶1000mm已占满10秒，尚未计入标记通过和阻塞时间。
3. 现有计距从近场确认开始，用户要求从可靠离开视野开始，起点不同。
4. 识别消失可能是漏检、遮挡、失帧或车身姿态变化，必须先证明标记末端向底部移动并真实离开，不能以Z从1变0就启动1米倒计时。
5. 轮子悬空虚增计距会导致过早DONE。
6. 本地docs/competition-rules.md摘要要求全车投影过线且停在过线后1米内。固定“视野末端后1米”不等同车体过线后1米；需要留下制动/标定余量。该依据是仓库现有规则摘要，本轮未重新核对原PDF或主办方更新。

建议状态机：首次过线只记起点并重武装；第二次确认返回后进入终点规划，保持循迹，以实际轮速/当前目标建立连续入口速度；可靠确认斑马线末端从底部离开后锁存剩余距离基准。后续按剩余可信距离降低目标速度，并在预计后轮已过线且到达停车目标后撤动力，不提前骤降到固定100。起点穿越策略与终点停车策略独立，不能因为共享marker_phase把起跑也当作停车制动。

拟议距离制动目标：v_limit=min(v_entry,sqrt(2*a_brake*d_remaining))；每10ms再经目标/输出斜坡，不因识别抖动重新抬高入口速度。终点入口速度与距离若不足，要提前减速，不能靠更大制动承诺强行停住。当前800mm/s²下，从1200降至0理论约900mm、1.5秒；只是恒定减速度模型，没有证明实车制动能力。以原有速度逐渐减速可接受，但必须同步校正终点超时、终点距离参数校验、最低可控速度和里程可信度。

额外1米可作为待实测参考窗口，不直接作为已满足比赛规则的保证。用户没有提供斑马线长度、相机到后轴实测距离及地面制动数据。可先采用带明显余量的可调目标，按后轮过线及实际停车点校准；没有这些数据不能给出唯一正确停车距离。
