# DRV8701E双电机与STEP/DIR编码器测试

当前默认已切换虚拟手柄遥控，C12用于本地允许/解除，不执行本页8秒测试。下文适用于`REMOTE_CONTROL_ENABLED=0`的独立测试模式；当前操作见 [遥控指南](virtual-remote-control.md)。

更新：2026-10-04。用户已安装逐飞官方DRV8701E双路模块至RT1064 V3.0主板的电机驱动1；左/右1024线带方向编码器接编码器1/2。最终确认：**车轮转1圈，啮合的编码器转4.25圈**，后轮直径64mm。早先“编码器直接装在轮轴、与轮同速”的说法已被用户纠正，不得用于换算。

## 程序入口与按键

应用模块为 [motor_control.c](../car/src/motor_control.c)、[encoder_feedback.c](../car/src/encoder_feedback.c)，参数分别位于 [motor_test_config.h](../car/config/motor_test_config.h)、[encoder_config.h](../car/config/encoder_config.h)。`main.c`完成初始化，PIT0每10ms处理电机测试与编码器采样。

| 按键 | 功能 |
| --- | --- |
| C12 / S5 | 稳定释放后新按下，启动一次测试；运行时再按可中止 |
| C14 / S3 | 电机停止优先，并锁存舵机停止请求 |
| C15 / S2 | 保留原舵机1480µs中值、±60µs按键摆动测试 |
| C13 / S4 | 保留Wi-Fi开关，上电默认OFF |

时钟建立后先初始化两路电机为零PWM；相机和应用初始化结束后才开放C12。按住C12上电、初始化期间按下或长按都不会自动启动；必须随后稳定释放再新按下。C12按下/释放以10ms采样进行30ms消抖，S3停止不消抖。重新启动测试会清零软件累计计数。

一次测试采用 **17kHz、10%占空比**，保持参考DIR高电平，按下表推进：

| 阶段 | 通道1 | 通道2 | 时间 |
| --- | --- | --- | --- |
| 1 | 10% | 0 | 2秒 |
| P | 0 | 0 | 1秒 |
| 2 | 0 | 10% | 2秒 |
| P | 0 | 0 | 1秒 |
| B | 10% | 10% | 2秒 |
| D | 0 | 0 | 自动结束 |

全程约8秒，由定时中断推进，不依赖主循环返回。中止状态显示S。当前是开环外设测试，编码器不参与闭环调速，不能当作赛道行驶控制。占空比配置限定1–150‰，当前100‰；实际电机是否能在10%起转待验证，不自动提高占空比。

S3在下一个正常10ms采样发出两路零PWM命令，库的整周期重载可能再等待约一个17kHz周期；长时间屏蔽中断或高优先级阻塞仍会推迟处理，因此不承诺硬实时10ms上界。舵机停止请求在主循环消费；Wi-Fi同步等待会延后舵机响应，但停止事件不会因按键已释放而丢失。

零PWM不是切断驱动电源，也不保证滑行、高阻或已物理停转。TI的DRV8701E真值表在nSLEEP有效时将EN=0定义为制动；逐飞模块的隔离电路/使能开关还需结合实物版本判断，不能把这一芯片条件当作所有模块状态的保证。

## 接线依据

主板 [硬件手册V1.0](<../参考/RT1064 V3.0主板硬件说明 V1.0.pdf>) PDF第13–14页与 [原理图V3.0.1.2](<../参考/RT1064主板V3.0.1.2 原理图.pdf>) 第4页已核对。

| 接口 | 针号与信号 |
| --- | --- |
| 电机驱动1 / P8 | 1=C8、2=C6、3=GND、4=GND、5=C9、6=C7 |
| 官方双驱通道1 | C8 / PWM2模块1A为PWM，C9为DIR |
| 官方双驱通道2 | C6 / PWM2模块0A为PWM，C7为DIR |
| 编码器1 / P13 | 1=GND、2=3V3、3=C0/STEP、4=C1/DIR；5/6不用 |
| 编码器2 / P12 | 1=GND、2=3V3、3=C2/STEP、4=C24/DIR；5/6不用 |

**官方电机通道1/2不等于已确认的左右轮。** 先通过单通道阶段观察哪个车轮转、L/R哪路计数变化。用户于2026-10-07确认两路参考HIGH方向均为车辆前进；编码器符号仍保留原始方向，当前不对左编码器自动乘−1。

电机接口P8提供控制信号，不替代驱动板的电源输入；主板驱动供电端子是电池电压。按实物丝印核对DRV8701E模块电源、信号和板载使能开关。编码器接口无防呆，重新插线时先断开全部电源，不能凭针数判断插头方向。

## 计数与速度换算

当前 [逐飞编码器驱动](../car/library/zf_driver/zf_driver_encoder.c)的`encoder_dir_init()`最终配置`kQTMR_PriSrcRiseEdgeSecDir`；[SDK定义](../car/library/sdk/drives/fsl_qtmr.h)说明它按主输入上升沿计数，第二输入决定方向。因此使用 **STEP ×1**，不按A/B四倍频计算。旧接口注释里“读取时DIR决定整窗正负”的说明与该硬件配置不符，本工程按实际实现处理。

参数与公式：

- 编码器每圈1024脉冲，车轮每圈计数 `1024 × 4.25 = 4352`。
- 64mm轮胎名义周长 `π × 64 ≈ 201.062mm`。
- 10ms增量为ΔN时：`计数/秒 = ΔN × 100`。
- `轮rpm = 计数/秒 × 60 / 4352`。
- `名义线速度mm/s = 计数/秒 × 201.062 / 4352`。

例如每秒4352计数对应60rpm和约201mm/s。这里4.25是**编码器与轮轴的转数比**，不是另行假定的电机减速比；不会重复乘除。实际PPR、啮合比和滚动周长仍可用手转一轮、滚动距离实测核对。

16位硬件计数器自由运行，软件求相邻采样的模差，避免每次“读后清零”漏掉中间边沿。有效采样前提是每10ms真实净变化绝对值小于32768；恰好半量程0x8000按−32768解释但方向有歧义，超范围不能可靠还原。累计计数按int32饱和并保留标志，换算中间量使用int64。主循环读取快照时短暂屏蔽并恢复原中断状态，不在临界区访问显示或网络。

速度是10ms原始窗口估算，没有滤波或测速闭环；低速时会有计数量化波动。正负仍表示原始电气方向，不代表已标定的前进/后退。

## 屏幕读数

测试期间及结束/中止后5秒，原顶部两行显示L（编码器1/左）、R（编码器2/右），每秒交替两组：

- 原始页：`d`为10ms带符号增量，`c`为计数/秒，`n`为本轮累计计数；`!`表示累计曾饱和，需要重新测试清零。
- 速度页：轮速rpm保留1位小数，线速度单位mm/s。

末尾阶段字符：1=通道1，2=通道2，B=双路，P=间隔，D=完成，S=中止。结束后统计仍持续采样，可观察停止命令后的残余转动；5秒后恢复TX/E/R和舵机状态行。摄像头图像区域及底部Wi-Fi状态保持原流程。若Wi-Fi阻塞主循环，屏幕更新会延后，定时电机流程仍运行。

## 首次使用

1. **将驱动轮架空**，确认驱动板电源、使能开关和编码器插接；保持Wi-Fi OFF进行首轮。
2. 重新打开 [工程](../car/autocar.uvprojx)，Rebuild后下载。新增了6个模块源/头/配置引用，需要重新加载工程。编译与自动化测试不等于实物接线验收。
3. 电机未启动时可手转各轮，核对接线；按C12后观察单通道阶段的车轮和L/R计数对应关系，再观察双路阶段。需要中止时按S3或再次按C12。
4. 若10%不转，先核对驱动使能、电池供电和PWM/DIR连接；若电机转而计数为0，核对STEP/DIR和编码器供电。记录“哪个通道转哪只轮、计数正负、变化量”，用于后续方向标定。

本任务没有自动烧录或驱动车辆。舵机中值与冻结图传均保留，后续调方向、PWM或闭环控制需要按具体任务授权进行。
