# 镜头组综合参考包分析（不计入84例程）

原包：[参考/镜头组例程.zip](../../参考/镜头组例程.zip)。分析直接从压缩包读取，不解压、不改动参考原件。原包使用 V3.5.5 的旧逐飞库；当前84例程库是 V3.11.2，不能把旧库整体覆盖进车辆工程。包内应用层共9个 `.c/.h` 文件如下；归档内部路径不能当作工作区可打开文件，表中给出完整路径便于在压缩包中定位。

| 包内路径 | 实际职责 |
|---|---|
| `demo/user/src/main.c` | 硬件初始化；完成帧复制、直方图、Otsu、二值化、扫描左右边界/中线、舵机比例转向、TFT诊断 |
| `demo/user/src/isr.c` | CSI与UART配置回调；PIT0每10ms读取清零左右编码器、位置式PID速度控制、DIR/PWM输出 |
| `demo/user/src/img_process.c` | `get_hist_gram`、`get_threshold_otsu`、`binaryzation_process`、`auxiliary_process`逐行扫线 |
| `demo/user/src/pid.c` | 参数初始化、位置式/增量式PID、float/short限幅；默认两轮共享Kp50、Ki0、Kd0，目标30 |
| `demo/user/inc/main.h` | 左右编码器、电机、舵机接线宏和舵机角度脉宽转换 |
| `demo/user/inc/isr.h` | 共享encoder_data_1~4变量的extern声明 |
| `demo/user/inc/img_process.h` | 图像处理函数声明与数据类型 |
| `demo/user/inc/pid.h` | PID结构和接口声明 |
| `demo/user/inc/RT106X_config.h` | 遗留配置头：PRINTF_ENABLE、旧USART_1调试宏、版本0x100；不能当作当前库版本或直接迁入 |

## 原参考的接线与参数

| 设备 | 原包配置 | 当前车迁入时 |

| 显示 | TFT180；`tft180_displayimage03x(image,125,100)` | 当前使用普通IPS200 SPI显示原始灰度，TFT180调用不迁入 |

| 右编码器 | QTIMER1_ENCODER2，A C2/B C24；读值取正号 | 验证输出模式、轮端每转计数、减速比及正方向 |
| 左电机 | DRV8701E式 DIR C7、PWM2_MODULE0_CHA C6，17kHz，GPIO_HIGH前进 | 与 [E3_04](motor.md#e3_04) 的MOTOR2接口对应；按实际主板DRV8701接法确认 |

| 调度 | PIT_CH0 10ms速度窗口；CSI新帧触发图像处理 | 电机任务与图像任务分别拥有有效性/超时管理 |

## 初始化、主循环与中断

`clock_init(600MHz)`、`debug_init` 后等待300ms，进入 `Init`：Flash初始化、TFT初始化、反复 `mt9v03x_init`、两路正交编码器、两路17kHz DIR/PWM、50Hz舵机、`My_Pid_Init`，最后打开PIT0 10ms。main随后开全局中断。原包没有启动门控，速度任务建立后会尝试驱动电机；不能落地直接启动参考代码。

每个新帧先将 `mt9v03x_image` 复制到独立 `image`，再计算256灰度桶直方图、Otsu阈值、逐像素二值化和逐行左右三连黑扫描。每行中线取左右边界均值，以上一行中点引导下一行；未找到边界时按代码的默认边界/图像中点处理。绘制左/中/右线后显示二值图。

转向仅取单行 `MT9V03X_H - MT9V03X_H/4`，默认120高即第90行（0起始索引）。偏差 `W/2 - mid_line[90]`，角度 `92.5 - 偏差×0.5×SERVO_DIR`，夹在85°与100°间后换为脉宽。它是单行比例转向，没有多行加权、曲率前馈、路口/环岛/坡道等元素状态机。

PIT0每10ms读左右编码器并清零，分别对 `speed_target-speed_real` 调 `PidLocCtrl(...,1.f)`。默认目标30表示30计数/10ms，不能直接当30cm/s；需按实测计数/轮转与轮径换算。默认Kp=50、Ki=Kd=0，积分和总输出参数各5000；输出仅取 `MAX(speed_pwm,0)`，方向固定前进。它没有允许倒转的制动控制和左右差速目标调度。`t=1`与10ms采样的关系需在迁入后统一，不能直接换成秒却沿用旧Ki/Kd。

CSI IRQ调用SDK采集处理；UART5按相机配置回调分发；其他模板IRQ仅列入口。速度控制独立于图像完成标志运行，丢图不会自动停车。

## 原包问题与使用限制

- `get_hist_gram` 使用 `memset(_hist_gram,0,256)`，而桶是 `short[256]`，只清一半字节；应按 `256*sizeof(*_hist_gram)` 清全数组。跨帧会残留高灰度桶，Otsu可能漂移。
- `PidLocCtrl` 先把积分限幅结果写入 `out_i`，后续又用未限幅的 `integrator` 计算并覆盖 `out_i`，积分限幅失效。Ki当前0暂时掩盖问题，启用积分前必须修正并验证抗饱和。
- 扫线未输出可靠的“赛道有效”质量指标；不能把默认中线当可靠观测。阈值退化、曝光变化、黑白颠倒、边界丢失、图像丢帧都需加入失效处理。
- 原代码没有元素识别、停车线逻辑、运行许可、急停或相机超时停车。没有完整赛用安全状态机；启动PIT会直接进入非零目标速度闭环。
- TFT调试和printf会耗时；只有单行比例转向，原车标定参数不能证明现车可用。Flash初始化本身不代表当前main做参数持久化。

车辆迁入版修正和实测范围以 [已知问题](../known-issues.md) 与主工程文档为准；以上分析描述保留的原参考，不声称它已修好或已编译通过。

## 分阶段测试与迁入方式

1. 先保持电机输出0，仅验证MT9V034帧更新、曝光、图像方向与串口/有线助手帧格式；无需屏幕。
2. 手转两轮测正反符号和一整轮计数，核对实际A/B模式，记录10ms增量单位。1024线、解码倍频与减速比必须分开记。
3. 舵机拆连杆/架空标定中位和机械两侧限位，确认偏差符号与纠偏方向；串口记录中线和目标角。
4. 架空逐路验证DRV8701输出、低占空比方向和停止，替换原包固定前进假设；启动条件满足后才允许闭环输出。
5. 修正直方图清零和积分限幅，给图像/编码器建立有效时间与超时，加入失效零输出；再逐步增加低速目标和方向增益。
6. 只迁应用算法与接口思路，基于V3.11.2统一库与车辆唯一ISR/main；用当前驱动重新校准全部引脚、频率、PWM单位和状态机。

预期结果按阶段观察：稳定帧、正确方向计数、单独轮速响应、可重复转向中位及丢帧零输出；这些是迁入验收目标，本次没有上板完成这些验证。
