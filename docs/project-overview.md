# 项目概况

## 定位与阶段

本工作区服务东南大学第二十一届智能车校赛备赛，当前以 RT1064 摄像头智能车工程为主线，覆盖嵌入式外设、图像处理、元素识别和闭环控制。其他组别的资料用于理解规则与学习，不表示应用工程已实现相应功能。

初始化前的 `car/autocar.uvprojx` 是空的 `Target1` 工程。当前已批准的工作是建立项目约定、整理资料与例程入口，并将逐飞依赖移植到 `car/` 以建立可构建的应用基础。应用与依赖已按下述结构移入主工程，实际编译结果、工具版本和后续更新以 [环境与构建](environment-and-build.md) 及 [日志](../logs/) 为准；编译成功不等于实车功能已验证。

当前任务：2026-10-08批准C15自动驾驶、视觉元素、双轮PID及斑马线一圈停车。保留C12遥控且互斥；M1左/M2右已确认，编码器符号尚待实测。参数初值和使用边界见 [自动驾驶指南](autonomous-driving.md)。

用户确认主板V3.0、SPI屏和7.4V电池，并授权配置电脑2.4GHz移动热点。DAP和USB不接、仅电池带摄像头/屏幕/Wi-Fi时电源灯全亮；原异常集中于DAP接入或上电顺序，尚未区分具体机制。沿用烧录后彻底断电、移除DAP排线，再仅用电池启动。

原始逐飞库的 [README](../SeekFree/RT1064_Library/README.md) 说明其工程依赖外置 SDRAM。这是核对核心板兼容性的重要条件，实际板级配置与核实结果应由硬件文档记录。不要仅根据套件链接或文件名判断主板版本、接线或电气参数。

## 目录职责

| 路径 | 职责 |
| --- | --- |
| `car/` | 主工作工程，可修改的应用与所采用的依赖副本 |
| `car/src/` | 应用实现、启动后的业务入口与中断对接 |
| `car/include/` | 应用对外头文件 |
| `car/config/` | 板级引脚、可调整参数与编译配置 |
| `car/library/` | 逐飞及 SDK 依赖副本，保留版本布局和授权 |
| `car/scripts/` | 可复现的构建、检查和辅助脚本 |
| `car/tests/` | 确有必要的算法、接口或集成验证材料 |
| `car/mdk/` | MDK 所需的启动、链接与相关工程支持文件 |
| `car/autocar.uvprojx` | MDK 主工程入口，构建细节由环境文档定义 |
| `参考/` | 原始规则、宣讲、购买建议、原理图和压缩包，保留原样 |
| `SeekFree/` | 原始逐飞仓库、例程和工具资料，保留原样 |
| `docs/` | 项目说明、规则、标准、硬件记录与例程索引 |
| `tmp/` | 任务专属临时目录，结束后清理任务目录，保留空根目录 |
| `logs/` | 按上海日期追加的 `.log` 修改记录 |
| `outputs/` | 持久交付物：`firmware/`、`reports/`、`backups/` |

以上应用目录是批准的组织结构；具体目录内容和工程引用以实际移植结果为准。`car/library/` 中 `sdk`、`zf_common`、`zf_driver`、`zf_device`、`components` 等保持依赖的原有层次，避免为统一命名而移动第三方文件。

## 后续推进条件

1. **工程基础：** 依据环境文档完成可复现构建，记录输出、诊断与工具来源。
2. **硬件对接：** 用户确认实物型号、接线、电源和执行器参数后，建立板级配置并验证外设。
3. **基础行驶：** 验证图像采集、编码器测速、舵机与电机控制，再闭环循迹。
4. **赛道元素：** 按正式规则验证十字、环岛、红砖、起跑和停车条件。
5. **调参与交付：** 保存参数依据、实车结果与最终固件，确保可追溯。

2026-09-30 已完成工程基础：Keil全量构建0错误0警告，19项算法检查及3项构建导出场景检查通过。尚未烧录或上板验证，其余阶段不视为完成。未解决问题以 [known-issues.md](known-issues.md) 为入口，实车验收必须说明测试场景和结果。
