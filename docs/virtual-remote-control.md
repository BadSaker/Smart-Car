# 逐飞助手虚拟手柄遥控

> 2026-10-08当前入口：[自动驾驶指南](autonomous-driving.md)。C15/S2改为自动驾驶启停，不再触发舵机摆动；C12在自动运行时停车，非自动模式维持遥控允许；S3最高优先停车。下文早期测试步骤按历史阶段理解。


当前默认`REMOTE_CONTROL_ENABLED=1`，使用现有Wi-Fi SPI和TCP Server连接。用户已确认两路原参考方向都是前进；舵机1480µs为中值，1420µs向右、1540µs向左。本次新增的是受本地允许、时限和换向保护约束的文本按键遥控，不是自动驾驶。

## 协议依据与功能边界

本地 [逐飞助手README](<D:/seekfree_assistant-V1.2.7/README.md>)“虚拟手柄”节，以及 [说明书V1.4](<D:/seekfree_assistant-V1.2.7/【文档】说明书/逐飞助手说明书 V1.4.pdf>) PDF48–50页，明确每次点击发送键名加CRLF。例如`W`发送十六进制`57 0D 0A`，`Up`发送`55 70 0D 0A`。

虚拟手柄默认只有8个按键，没有已证实的模拟轴、释放帧、发送时间戳、序号或周期心跳。说明书基于软件V1.2.0，随本机V1.2.7包提供；包内更新日志不能证明长按发送方式已经改变。因此**不承诺按住就持续发送，也不承诺松手立即发停车包**。下列车辆动作映射和超时为本工程选择，非官方协议定义。

## 按键映射

| 助手默认按键 | 车辆动作 |
| --- | --- |
| W／蓝色三角 | 前进，双路最高10%占空比，保留当前有效转向 |
| S／蓝色五角星 | 后退，双路最高10%占空比，保留当前有效转向 |
| A／蓝色爱心，或Left／左箭头 | 左转目标1540µs，不续期油门 |
| D／蓝色圆圈，或Right／右箭头 | 右转目标1420µs，不续期油门 |
| Up／上箭头 | 回中目标1480µs，不续期油门 |
| Down／下箭头 | 零油门并回中；也是本地解锁后的停车确认 |

本工程规定上箭头回中、下箭头停车；前后行驶使用W/S。每条W/S只提供最多300ms驱动许可，新的W/S才续期。若助手持续发有效W/S，程序可连续续期；没有新W/S就自动给两路零PWM。因此单击是短时点动，方向键或未知报文不会让电机一直运行。

转向活动时间为1.5秒，命令限幅在1420–1540µs，按每20ms最多2µs渐变。实际到位时间还受主循环周期影响；图传阻塞时不能保证及时到位。转向超时清除旧目标并停止更新PWM，S-U400失去信号后仍可能保持原位置。需要主动回中使用Up或Down。

## 本地控制和使用步骤

| 主板按键 | 遥控模式 |
| --- | --- |
| C13／S4 | Wi-Fi开关，上电默认关闭 |
| C12／S5 | 本地允许／解除遥控；上电或长按不会自动允许 |
| C14／S3 | 优先停止电机、解除允许，并锁存舵机停止请求 |
| C15／S2 | 遥控模式下不启动原舵机摆动测试 |

1. 首轮将驱动轮架空，保持现有6.0V舵机供电和已经验证的DRV使能状态。重新打开 [car/autocar.uvprojx](../car/autocar.uvprojx)，Rebuild后由用户下载；新增了5个源/头/配置引用。
2. 开启电脑已配置的2.4GHz热点，逐飞助手选择网络TCP Server，本机`192.168.137.1`（或绑定全部地址），端口8080，点击侦听。
3. 主板按C13开启Wi-Fi，等待TCP连接。保持原图传连接，可在助手“拓展工具”中选择“开启手柄”，确认当前发送客户端为本车连接。
4. 主板按C12允许遥控。程序先排空旧输入，屏幕显示`RC:WAIT Down=STOP to enable`后，在虚拟手柄点击下箭头或按Down，确认零油门。
5. 屏幕进入`RC:ON`后，用W/S短时前后移动、A/D或左右箭头转向、Up回中、Down停车。使用键盘时必须让虚拟手柄窗口处于激活状态；保留默认快捷键绑定，组合键及其他名称不会作为有效控制命令。
6. C12可解除遥控，S3可停机。Wi-Fi关闭、重连、接收异常或主循环长时间停顿后，都需要重新C12允许，再发送新的Down确认。

Down停车后本地允许可保持，下一条新W/S能够再次点动；S3、断链和C12解除则必须重新本地允许。换向先发零PWM，至少间隔100ms再切DIR；这不是对机械已经完全停转的测量结论。

## 屏幕与模式选择

顶部第一行显示遥控连接/允许/排空/等待Down状态；允许后显示`T:.../1000`与累计有效命令数RX，100/1000为10%，负值为后退。第二行显示当前舵机命令脉宽，0表示无PWM。原摄像头图像区域及底部Wi-Fi提示保留。

配置入口：[remote_control_config.h](../car/config/remote_control_config.h)。设`REMOTE_CONTROL_ENABLED=0`并重编译，可恢复原C12电机/编码器有限测试和S2舵机测试，见 [电机指南](motor-encoder-debugging.md) 与 [舵机指南](servo-debugging.md)。两种模式互斥，不由两套逻辑同时写电机/舵机。

## 输出保护与限制

- 电机300ms时限、S3停止和100ms换向间隔由PIT0处理，不依赖主循环是否返回；关中断、CPU异常仍会影响软件时序，不能作为硬件急停。
- 新连接或本地重新允许后，先丢弃旧字节直到实际读到空，再等新的Down。忙状态不当成空；同一批收到Down后，后续行驶命令不执行。
- 每圈最多向应用取64字节；一次读取超过50ms或返回长度异常时丢弃结果并撤销遥控。主循环超过300ms未服务遥控时也撤销允许、清除半行并重新排空，避免停顿恢复后消费本机积压。
- 只接受精确大小写、CRLF结尾的8种键名；过长、非法字符、未知键和不完整报文不续期。没有把`Up`的0x55首字节误当成调参二进制帧头，也没有并行调用另一个消费者抢同一Wi-Fi FIFO。
- 原Wi-Fi连接与发送仍是同步流程，接收也调用供应商接口；读取预算不等于底层函数严格硬实时上界。电机时限独立，屏幕与舵机响应可能延后。
- 原文本协议没有发送时间戳或身份认证，固件只能按接收时刻处理。局部排空和停顿保护不能证明延迟TCP报文的真实发送时间；仅在已配置、可信的调试网络和可观察范围内测试。
- 零PWM不保证断电、高阻或物理立即停转；舵机撤销信号不保证卸力。本任务未自动烧录或操作实车。
