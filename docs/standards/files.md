# 文件与目录标准

## 放置原则

| 内容 | 位置 | 要求 |
| --- | --- | --- |
| 应用实现 | `car/src/` | 只放本项目业务逻辑，按功能分模块 |
| 应用头文件 | `car/include/` | 声明公共接口，避免泄露内部状态 |
| 引脚、参数、编译开关 | `car/config/` | 标明单位、依据与确认状态 |
| 第三方依赖 | `car/library/` | 保留逐飞与 SDK 层次、版权、授权及版本信息 |
| 构建或检查脚本 | `car/scripts/` | 记录运行入口、环境依赖和结果位置 |
| 必要的验证材料 | `car/tests/` | 与实际风险或验收要求对应 |
| MDK 支持文件 | `car/mdk/` | 启动、链接等文件按工程实际引用放置 |
| 构建缓存 | `car/build/` | Keil 输出与中间件；不提交，可清理后重建 |
| 人工维护说明 | `docs/` | 长期结论与索引；不堆叠临时过程输出 |
| 本任务中间材料 | `tmp/<task-name>/` | 结束后删除该任务目录 |
| 每日修改日志 | `logs/YYYY-MM-DD.log` | 只追加，使用上海时区；单次运行过程日志不入库 |
| 最终固件 | `outputs/firmware/` | 附目标、工具版本、来源与验证结果 |
| 最终报告 | `outputs/reports/` | 可独立阅读的验收、诊断与整理报告 |
| 持久备份 | `outputs/backups/` | 仅确需存档时使用；默认以 git 提交留痕，不逐次生成整包备份 |

主工程入口固定为 `car/autocar.uvprojx`。构建产生的对象、清单、映射文件按 [环境文档](../environment-and-build.md) 管理；不因“看起来是输出”而自行删除既有目录。

## 来源与编码

- `参考/`、`SeekFree/` 是原始来源，保持原样；需要修改时先形成 `car/` 中的可追溯副本。
- 最新已采用库版本及源提交在项目记录中明确。库升级和旧参考例程移植是不同工作，不把 V3.5.5 文件无说明地混入 V3.11.2 依赖。
- 上游 [LICENSE](../../../SeekFree/RT1064_Library/LICENSE) 为 GPL v3 文本；复制依赖时保留授权文件和原版权声明。具体依赖也可能附自己的授权文件，须一并保留。
- 新应用代码、脚本和文档使用 UTF-8；既有 GBK 文件保持编码，编辑前确认编码。禁止以批量转码解决显示问题。
- 版本控制由用户本人执行，不自动 `add/commit/push`；禁止修改上游嵌套 Git（`SeekFree/` 内）。变更留痕以 git 提交与每日日志为准。

## 文档与产物

`simulation/`维护桌面桥接、图像/车辆模型及实验界面，C算法统一读取`car/`。本地热点头文件、工具路径、外部参数登记、工具链二进制、缓存及运行输出由.gitignore管理。原始实测图保存在`simulation/assets/measurements/`；正式报告、固件和备份继续进入outputs。本机取消Git跟踪不授权删除持久资料或改写历史。

同一事实只指定一个主维护位置：环境命令在环境文档，引脚在硬件文档，规则在规则文档，待解决问题在问题文档。其他文档通过链接引用。

仿真启动、解释器及编译器发现的本机诊断进入`simulation/runtime/`，日常实验导出进入`simulation/runs/`；两者不充当正式报告。验收中间材料仍进入`tmp/<任务名>/`，完成后只清理本任务材料。旧`simulation/reports/`与`simulation/backups/`已于2026-10-14按原字节迁入outputs的历史归档；原路径索引保留，不批量改写历史正文。PowerShell脚本含中文时使用UTF-8 BOM以兼容Windows PowerShell 5.1，不批量转换第三方文件。

最终交付物应能追溯到本次改动和验证；编译产物注明是否经过实车验证。日志记录过程，报告整理结论，两者不能互相替代。文件链接优先采用相对路径，外部路径或工具位置以环境文档中的已验证记录为准。

## 报告精简

`outputs/reports/`仅保留重要验收、兼容性等主要报告，按 [命名规范](naming.md#文件命名规范) 标注日期。重复的机器校验JSON、逐文件清单与构建map不作为长期报告保留；必要的来源、版本和校验摘要并入主报告。链接map留在本任务构建临时目录，任务完成后清理。
