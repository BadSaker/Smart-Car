# 应用代码标准

## 模块边界

- 应用逻辑位于 `car/src/`、`car/include/`，板级映射与调参值位于 `car/config/`。
- 保留第三方库接口与布局。优先通过应用封装适配硬件，确需修改依赖时记录文件、原因、来源版本及验证。
- 图像采集、图像处理、元素识别、速度估计、转向控制和电机控制分别提供清楚的输入、输出及调用周期。
- 业务层避免直接散布引脚、PWM 通道和设备地址；硬件配置与算法参数分开管理。
- 初始工程提供的默认配置属于工程选择，只有与实物核对并测试后才可标记为已验证。

## 实时执行

中断仅完成必须的采样、状态更新、缓冲交接或短周期控制。耗时图像处理、阻塞通信和大量打印放在适当的主循环或任务中，记录其周期预算。避免在中断中加入无界循环、等待外设就绪或动态分配。

共享缓冲要明确所有权和完成标志，图像帧就绪后再处理，避免采集与处理覆盖同一数据。`volatile` 用于确有异步变化的对象，不将其当作多步操作的互斥措施。需要原子交接或临界区时说明作用范围与时间。

## 数据、控制与故障

- 对索引、图像坐标、队列长度和数组范围进行约束；越界或无有效边线时给出明确状态。
- 参数写明单位与取值范围。像素偏差、角度、角速度、编码器计数、速度和 PWM 输出不能混用。
- 控制输出统一限幅；积分环节处理饱和及状态切换，不能将未知极性或方向直接视为正确。
- 元素状态机采用明确枚举与转移条件；记录进入、退出和异常恢复条件，避免散布魔数。
- 失帧、无有效路径、测速异常和传感器失败需有可检查的状态及处理路径，具体动作由批准设计和实车验证确定。
- 调试输出应可关闭并控制频率，不让串口、屏幕或图传改变控制周期。正式计时按规则移除无线模块。

## 可读性与验证

工程自有代码（src、include、config、scripts、tests）的说明性注释和文档字符串统一使用中文；接口标识符、技术缩写及版权/许可证原文保留，第三方库不为此批量翻译。注释说明意图、单位、约束和依据；不要逐行重复代码。公共接口说明输入、输出、失败行为、调用位置及共享状态。新文件使用 UTF-8，原有 GBK 文件保持原编码；保留第三方版权注释。

修改后执行与风险相符的验证：接口和工程变更核对编译诊断，算法变更采用代表性输入或轨迹，硬件控制变更按已批准范围做实物核对与测试。低影响、可逆修改不要求机械增加测试文件；未执行的实车验证应明确记录。最终结果按 [workflow.md](workflow.md) 交付。
