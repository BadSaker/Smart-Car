## 简洁实现与行驶连续性

按用户2026-11-05明确要求，后续编写和修改代码以简洁、直接、实车控制有效为优先，抛弃默认叠加保守策略的做法。先删除或合并多余逻辑，再考虑新增机制；代码更少应来自职责清楚、路径直接，而不是压缩排版或省略必要说明。

- 不为假设中的异常不断增加判断、确认帧、状态、超时、恢复门槛和备用分支。新增机制必须对应明确需求或已复现的问题，并说明它会怎样影响转向响应、动力输出和恢复行驶。
- 正常循迹与执行器更新是主线，不能等待所有元素判断同时通过；元素识别、显示、图传和诊断不得成为正常控制必须等待的前置条件。优先消除串行等待、重复握手和重复限幅/平滑，不再用额外门槛修补这些机制带来的延迟。
- 停车、撤动力和限速策略以用户明确要求为准。不得以“更保守”或“更安全”为由，擅自补回已取消的LOST等识别锁停，或把普通识别波动扩展为停车条件。已有策略也要检查是否造成不必要的停走、低速滞留或旧方向保持。
- 一个职责优先保留一套明确实现。功能撤销或替换时，同步清理失去用途的计数器、状态字段、接口、兼容分支和测试，不长期堆积历史机制；必要的诊断应直接回答当前问题，不建设无实际用途的框架。
- 简化以控制行为和证据判断：能删除的直接删除，能合并的合并；有明确用途的数组边界、单位换算和执行器输出范围检查不因行数少而省略。不能凭判断数量推断耗时，应区分计算耗时、阻塞等待和策略主动撤动力。
- 验证优先检查实际响应和连续行驶，包括转向是否及时、是否无故撤动力、恢复是否拖延；编译通过或主机测试数量增加不能替代这些结果。未经验证的影响如实标注，不用新增保守逻辑代替验证。

2026-11-06职责约定：视觉负责从图像选路并提供像素偏差，转向与轮速PID负责执行。识别条件可以决定选哪条边，但不得重新变成评分许可、限速/撤动力前置条件；不恢复多档恢复速度、重复目标/PWM/舵机渐变。简化不能靠删掉已证实必需的选路几何，再不断添加例外补丁；用实际灰度与闭环结果验证取舍。

## 模块边界

- 应用逻辑位于 `car/src/`、`car/include/`，板级映射与调参值位于 `car/config/`。
- 保留第三方库接口与布局。优先通过应用封装适配硬件，确需修改依赖时记录文件、原因、来源版本及验证。
- 图像采集、图像处理、元素识别、速度估计、转向控制和电机控制分别提供清楚的输入、输出及调用周期。
- 业务层避免直接散布引脚、PWM 通道和设备地址；硬件配置与算法参数分开管理。
- 初始工程提供的默认配置属于工程选择，只有与实物核对并测试后才可标记为已验证。

## 实时执行

中断仅完成必须的采样、状态更新、缓冲交接或短周期控制。耗时图像处理、阻塞通信和大量打印放在适当的主循环或任务中，记录其周期预算。避免在中断中加入无界循环、等待外设就绪或动态分配。

共享缓冲要明确所有权和完成标志，图像帧就绪后再处理，避免采集与处理覆盖同一数据。`volatile` 用于确有异步变化的对象，不将其当作多步操作的互斥措施。需要原子交接或临界区时说明作用范围与时间。

## 数据、控制与故障

- 对索引、图像坐标、队列长度和数组范围进行约束；越界或无有效边线时给出明确状态。
- 参数写明单位与取值范围。像素偏差、角度、角速度、编码器计数、速度和 PWM 输出不能混用。
- 控制输出统一限幅；积分环节处理饱和及状态切换，不能将未知极性或方向直接视为正确。
- 元素状态机采用明确枚举与转移条件；记录进入、退出和异常恢复条件，避免散布魔数。
- 失帧、无有效路径、测速异常和传感器失败需有可检查的状态及处理路径，具体动作由批准设计和实车验证确定。
- 调试输出应可关闭并控制频率，不让串口、屏幕或图传改变控制周期。正式计时按规则移除无线模块。

## 可读性与验证

工程自有代码（src、include、config、scripts、tests）的说明性注释和文档字符串统一使用中文；接口标识符、技术缩写及版权/许可证原文保留，第三方库不为此批量翻译。注释说明意图、单位、约束和依据；不要逐行重复代码。公共接口说明输入、输出、失败行为、调用位置及共享状态。新文件使用 UTF-8，原有 GBK 文件保持原编码；保留第三方版权注释。
