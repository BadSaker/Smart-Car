# 命名与单位标准

## 文件命名规范

本页统一维护项目自有文件的命名规则、接口标识符与单位约定。新增或经审核重命名的文件按用途选择对应规则。

- 文件名必须清晰直观，能看出对象、用途或内容；优先使用完整英文单词，允许 `pid`、`pwm`、`uart` 等通用技术缩写，禁止自造含义不明的缩写、拼音简写和纯编号。
- 禁止使用 `新建文件`、`data1`、`temp2`、`final2`、`最终版`、`最终修改版` 等不能说明内容或版本的名称；需要区分版本时使用明确的日期、时间戳或版本号。
- 除固定名称和第三方原名外，使用小写英文、数字及下表指定的分隔符，不含空格；扩展名必须与实际格式一致，不仅靠大小写区分文件。

| 文件类型 | 命名规则 | 示例 |
| --- | --- | --- |
| 源码、头文件（`.c`、`.h` 等） | 小写英文加下划线，表达模块与职责；配对的实现和头文件使用相同主名 | `motor_control.c`、`motor_control.h` |
| 配置（`.h`、`.json`、`.yaml`、`.ini` 等） | `<对象>_config.<扩展名>`，必要时在对象中注明场景 | `board_config.h`、`camera_config.json` |
| 脚本（`.ps1`、`.py`、`.sh` 等） | `<动作>_<对象>.<扩展名>`；既有单一入口 `build.ps1`、`test.ps1` 保留 | `check_links.ps1`、`export_firmware.py` |
| 测试代码 | `test_<被测模块或行为>.<扩展名>`，对象内部使用下划线 | `test_pid.c`、`test_build_script.py` |
| 说明文档（`.md`、`.pdf`、`.docx`、`.pptx` 等） | 小写英文加连字符，直接表达主题 | `camera-calibration.md`、`hardware-overview.pdf` |
| 验证、诊断报告 | `<主题>-YYYY-MM-DD.<扩展名>`；同日多次交付需区分时增加 `-HHmmss` | `encoder-validation-2026-09-30.md` |
| 图片、图表 | `<对象>-<内容或场景>.<扩展名>`；采集或实验记录增加 `_YYYYMMDD_HHmmss`，连续帧再加 `_0001` 等序号 | `camera-mounting.png`、`track-crossing_20260930_153000_0001.png` |
| 数据、清单（`.csv`、`.xlsx`、`.json` 等） | 小写英文加连字符，说明对象和内容；采集数据增加 `_YYYYMMDD_HHmmss` | `source-manifest.json`、`encoder-speed_20260930_153000.csv` |
| 日志（`.log`） | 每日修改日志固定为 `YYYY-MM-DD.log`；工具运行日志为 `<工具或任务>.log`，归档增加 `-YYYYMMDD-HHmmss`，需要时再加毫秒 | `2026-09-30.log`、`keil-build.log`、`keil-build-20260930-153000-123.log` |
| 固件（`.hex`、`.bin`、`.axf`） | 构建脚本固定输出 `autocar.<扩展名>`；归档为 `autocar_<用途>_YYYYMMDD_HHmmss.<扩展名>`，用途内部使用下划线；同次构建的各格式主名一致 | `autocar.hex`、`autocar_camera_debug_20260930_153000.hex` |
| 备份文件或目录 | `<来源>_<用途>_YYYYMMDD_HHmmss[.<扩展名>]`，来源与用途内部使用连字符 | `car_before-config-change_20260930_153000.zip` |

- 按文件用途选择规则：配置、测试、报告、备份等专用规则优先于通用扩展名分类；未列出的项目自有文件按最接近的用途命名，并在需要时补充本表。
- 日期统一为 `YYYY-MM-DD`；紧凑时间戳中的 `YYYYMMDD` 表示年月日，`HHmmss` 表示24小时制时分秒，均使用 Asia/Shanghai。同名归档不得覆盖，必要时增加毫秒或有意义的场景说明。
- 保留 `AGENTS.md`、`README.md`、`LICENSE` 等约定名称，以及 `autocar.uvprojx`、`autocar.uvoptx`、工具固定配置名和自动生成文件名；工具管理的中间产物遵循工具命名。
- `参考/`、`SeekFree/` 和 `car/library/` 等第三方文件保留原名。已有项目文件不因本规范自动批量改名；确需重命名时另行提交范围审核，并同步工程引用、脚本路径和文档链接。
- 文件名只说明内容、用途和标识，不代表已完成实车验证；工具版本、源版本及验证状态写入报告或日志。文件存放位置仍按 [文件规范](files.md) 执行。

## 接口与标识符

| 对象 | 新应用约定 | 示例 |
| --- | --- | --- |
| 函数、变量、字段 | 小写下划线，必要时带模块前缀 | `motor_set_pwm`、`frame_ready` |
| 类型 | 小写下划线，采用 `_t` 后缀 | `track_state_t` |
| 宏、枚举成员 | 大写下划线，带模块前缀 | `MOTOR_PWM_LIMIT`、`TRACK_RING_ENTER` |
| 头文件防护宏 | 路径或模块名称加 `_H` | `AUTOCAR_MOTOR_CONTROL_H` |

公共接口使用模块前缀避免冲突。函数名表达动作，布尔状态表达条件；避免 `data1`、`temp2` 等无法说明用途的名称。第三方 API 调用遵循其现有名称，不改写库接口。

## 参数与坐标

- 含单位的量在名称或接口注释中明确单位，如 `sample_period_ms`、`yaw_rate_dps`、`distance_mm`。
- PWM 若使用计数或库规定范围，明确该范围；不能把计数直接称为百分比。
- 图像坐标明确 `row`、`col` 或 `x`、`y` 的定义与原点，注明像素单位和索引边界。
- 左右、电机正反转、舵机正向等方向在配置文档中定义，不能依赖接线猜测。
- 循迹偏差说明正负号、归一化方式及坐标来源；阈值写明尺度。

## 任务与产物

临时目录使用清楚的任务名称，如 `tmp/project-init/`，每个任务只清理自己的目录。每日修改日志与工具运行日志用途不同，命名及归档按 [文件命名规范](#文件命名规范) 执行；每日修改日志按 Asia/Shanghai 日期划分并只追加。

固件的固定构建输出与带时间戳的归档副本按上述规范区分；实际构建输出路径以 [环境与构建](../environment-and-build.md) 为准。工具版本、源版本和验证状态写入随附报告或日志，避免在名称中塞入长串不可读信息。持久备份注明来源与用途，存放位置详见 [files.md](files.md)。
